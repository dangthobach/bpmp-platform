# Authoring Service: process and decision model draft slices

**Status:** internal Authoring Protobuf, Go application/gRPC/PostgreSQL adapters for BPMN, DMN and JSON-schema forms, immutable source-version publication, version-history metadata pagination and source retrieval, actor-proof verifier, signed Authz bundle PEP/cache/consumer, dynamic owner-manifest loader, migrations, and a fail-closed Go process bootstrap are implemented and compile. A bounded Compiler gRPC contract and Rust compiler server validate BPMN and DMN with required mutual TLS. Gateway routes and Modeler UI cover BPMN/DMN drafts and versions plus form draft create/save/validate/publish/version history. Tasklist loads a published form by `form_key`, pins the submitted form version, and sends typed outputs; Gateway checks the pinned version and validates outputs before Human Runtime accepts completion. Gateway only registers these routes when `authoring_address` is configured. Deployment activation, provisioned production path and end-to-end verification remain outstanding; check-in does not create a signed WIR artifact or activate a process.

## Ownership

Authoring owns tenant-scoped process/decision model metadata, mutable BPMN/DMN drafts and immutable BPMN/DMN source-version snapshots. The compiler owns BPMN/DMN/CMMN interpretation and WIR generation. Engine owns workflow activation and runtime state. A draft save must never activate a workflow; source check-in must never imply deployment; deployment must remain a separate accepted command/job with a signed immutable runtime artifact.

## First internal API

Source: `contracts/proto/bpmp/authoring/v1/authoring.proto` (`bpmp.authoring.v1.AuthoringService`).

| RPC | Intent | Enforcement and state |
|---|---|---|
| `ListProcessModels` | Tenant-scoped keyset page and bounded search | Verify actor proof; require `authoring.listProcessModel`; exclude tombstones unless separately authorized |
| `CreateProcessModel` | Create a model and initial BPMN draft | Require command/idempotency/correlation IDs and `authoring.createProcessModel`; server generates UUIDs and audit metadata |
| `GetProcessModel` | Read model and current draft | Tenant-scoped ID lookup; non-visible IDs return the same response as missing IDs |
| `SaveProcessModelDraft` | Replace draft source using a compare-and-swap revision | Require `authoring.saveProcessModelDraft`; same idempotency key + digest replays the original response; key reuse with a different digest conflicts |
| `ValidateProcessModelDraft` | Validate exactly the requested persisted revision | Require `authoring.validateProcessModel`; stale revision is rejected; validation output is attached only if the draft still has that revision |
| `CheckinProcessModel` | Freeze one saved BPMN revision as an immutable source version | Require `authoring.checkinProcessModel`; revision, compiler `VALID` state and caller-provided SHA-256 are rechecked in one transaction; unique version tag, idempotency, latest-version pointer and audit evidence commit with the snapshot |
| `ListProcessModelVersions` / `GetProcessModelVersion` | Browse version metadata, then retrieve one selected source snapshot | Separate list/read capabilities; listing is newest-first and paginated without XML; detail verifies tenant, model and version identity before returning the immutable source |
| `CheckinDecisionModel` | Freeze one saved DMN revision as an immutable source version | Require `authoring.checkinDecisionModel`; revision, compiler `VALID` state and caller-provided SHA-256 are rechecked in one transaction; unique version tag, idempotency, latest-version pointer and decision audit evidence commit with the snapshot |
| `ListDecisionModelVersions` / `GetDecisionModelVersion` | Browse version metadata, then retrieve one selected DMN source snapshot | Separate list/read capabilities; listing is newest-first and paginated without XML; detail verifies tenant, model and version identity before returning the immutable source |
| `ListDecisionModels` | Tenant-scoped keyset page and bounded search | Verify actor proof; require `authoring.listDecisionModel`; exclude tombstones |
| `CreateDecisionModel` | Create metadata and initial DMN draft atomically | Require `authoring.createDecisionModel`; command/idempotency digest and audit evidence are committed with the model |
| `GetDecisionModel` | Read metadata and current DMN draft | Tenant-scoped lookup and separate model/draft read capabilities |
| `SaveDecisionModelDraft` | Replace DMN source at an expected revision | Require `authoring.saveDecisionModelDraft`; CAS, idempotency replay and audit are enforced by the owner transaction |
| `ValidateDecisionModelDraft` | Validate exactly the requested persisted DMN revision | Require `authoring.validateDecisionModel`; compiler diagnostics persist only while the revision is unchanged |
| `ListForms` / `GetForm` | Browse form definitions and inspect the current draft | Tenant-scoped metadata/draft read with separate capabilities |
| `CreateForm` / `SaveFormDraft` | Create and update JSON Schema form drafts | Compare-and-swap revision, idempotency digest and immutable audit evidence |
| `ValidateFormDraft` | Validate a persisted form draft at an exact revision | Validation command is idempotent and audited; a stale revision is rejected |
| `PublishForm` | Publish a validated draft as an immutable version | Revision and digest are rechecked in a serializable transaction with latest-version pointer, dedup and audit |
| `GetFormByKey` | Resolve a BPMN form key to its current published snapshot | Runtime read returns only published versions; requires `authoring.getPublishedForm` |
| `ListFormVersions` / `GetFormVersion` | Browse immutable form history and read a selected version | Tenant, form and version identities are checked together |

`ActorProof` is passed end-to-end. The Authoring service must verify it itself and enforce capability + tenant/resource scope. Gateway capability filtering and UI visibility are not final enforcement. The signed proof actor, not a request field, supplies `created_by` and audit actor.

## Initial persistence slice

Migrations: `db/authoring-service/migrations/001_process_model_drafts.sql` through `005_forms.sql`; 001–004 establish BPMN/DMN drafts and immutable source versions, and 005 adds form definitions, drafts, immutable versions and append-only form audit evidence.

- `process_models` is tenant-scoped, UUID-keyed, soft-deletable, audited and row-versioned. `model_key` is unique within a tenant and is not recycled after tombstoning.
- `process_model_drafts` stores one mutable BPMN source per model, its monotonic draft revision, optional immutable base-version reference, bounded diagnostics, and validation state. Source is limited to 1 MiB at the database boundary as defense in depth.
- When a BPMN draft declares a base version, Authoring resolves that version under the same tenant/model inside the save transaction and requires byte-identical source before recording the lineage; a client cannot attach an unrelated version ID to different BPMN text. The audit records the base version alongside the new revision.
- `process_model_versions` stores immutable BPMN source snapshots keyed by tenant/model/version, with source revision, SHA-256, creator, timestamp, unique version tag and summary. A model's latest-version pointer is a tenant-scoped foreign key; database triggers reject version update/delete. Check-in and its audit/dedup evidence share a single serializable transaction.
- `decision_model_versions` applies the same immutable snapshot, source revision, SHA-256, unique tag, latest-version pointer and serializable audit/idempotency transaction to DMN. The source revision represented by the latest immutable snapshot is returned in decision model metadata so a reloaded UI can suppress duplicate check-in.
- Version-history list queries return bounded metadata pages ordered by descending unique `version_num`; opaque cursors carry only the last version number, so random UUID ordering cannot skip or duplicate rows. Version-source reads require the version ID to belong to the requested tenant and parent model. Soft-deleted models do not expose history through these APIs.
- `authoring_command_dedup` binds idempotency key and command ID to operation, request digest and the first response.
- `authoring_audit_evidence` is append-only and belongs to the same tenant/model. Draft save, model create, validation and later deployment evidence must use the owner transaction where a durable state transition occurs.
- `decision_models` and `decision_model_drafts` provide the equivalent tenant-keyed metadata and one mutable DMN draft per model. DMN revisions use the same CAS and idempotency command table. `authoring_decision_audit_evidence` is append-only and scoped by tenant/model.

The supported form schema profile has an object root, 1–128 properties, primitive `string`/`integer`/`boolean` fields or arrays of those primitive types, explicit `additionalProperties: false`, and required names that exist in `properties`. Schema and UI schema payloads are each capped at 256 KiB. Gateway validates submitted required fields, exact property names, primitive/list types, enum, string length, array size, and numeric bounds against the current published version ID included in completion; Engine persists that version ID with the completion event. The versioned UI schema profile is intentionally bounded: `{ "order": ["fieldA"], "fields": { "fieldA": { "widget": "textarea", "width": "full", "placeholder": "…", "help_text": "…" } } }`. `order` may name only declared fields and may not repeat a field; omitted declared fields render afterward in JSON Schema property order. Field settings may only use `widget`=`default|textarea`, `width`=`full|half`, `placeholder` (256 characters max), and `help_text` (512 characters max). Textarea is valid only for non-enum string fields. Authoring validation rejects unknown properties, fields, widgets and incompatible widget/type combinations; Tasklist renders this profile, while server-side JSON Schema validation remains authoritative for submitted values. Arbitrary HTML, scripts, custom components and unconstrained layout are not supported. The version check is at submission: a newly published version can make an already-open task form stale; activation-time pinning is not implemented. Signed WIR artifacts, deployment jobs, called-process dependencies, outbox publication and retention operations remain outside the implemented schema.

## Required implementation gates

1. Deploy the Authoring bootstrap and compiler server with provisioned PostgreSQL, unique-per-replica Kafka consumer groups, workload mTLS certificates, actor proof keys, JWT JWKS/issuer/audience policy, and signed bundle trust keys. The service executable is `apps/go/authoring-service/cmd/authoring-service`; its config is strict JSON and can optionally apply the initial migration once under a PostgreSQL advisory lock.
2. Register the exact `authorization-owner-manifest.json` with Authz and publish a matching signed bundle. At runtime, the service derives capability-to-resource/action routing and the canonical manifest digest from that file; a stale or differently-versioned catalog entry fails authorization closed. Changing manifest entries requires a new manifest version and a matching Authz catalog/bundle publication.
3. Configure Gateway `authoring_address` and `upstream_tls.authoring_server_name`, issue the matching client certificate allowlist entry in Authoring, and deploy both services. Until that configuration exists, Authoring endpoints are omitted and the Modeler shows an explicit unavailable message.
4. Add PostgreSQL integration tests for tenant isolation, duplicate/replayed command, changed payload under reused key, concurrent revision writes, tombstone visibility, compiler diagnostics and stale-validation races.
5. Add signed WIR artifact generation and deployment only after compiler artifact signing, Engine activation semantics, rollout/rollback, and immutable deployment evidence are specified and exercised. BPMN source check-in is already available but must not be treated as deployable runtime output.

## Compiler boundary

Contract: `contracts/proto/bpmp/compiler/v1/compiler.proto`. The Rust `bpmn-compiler-server` delegates BPMN and standalone DMN syntax/table validation to the existing bounded compiler implementation, and requires a server certificate, client CA, and private key at startup (`BPMP_COMPILER_TLS_CERT`, `BPMP_COMPILER_TLS_KEY`, `BPMP_COMPILER_CLIENT_CA`). Authoring sends tenant, model, and exact draft revision; diagnostics persist only through the revision-checked owner transaction. The server returns structured line/column diagnostics and never activates or publishes a model. Production bootstrap still needs deployment-specific certificate issuance/rotation, workload identity restrictions, limits, telemetry and resource isolation.

## Bootstrap configuration and readiness

The Authoring executable requires TLS for its inbound Gateway connection, outbound Compiler connection, and Authz Kafka connection. Inbound gRPC checks both the client CA chain and an explicit SHA-256 leaf-certificate allowlist. PostgreSQL and Kafka are probed before serving; readiness is `GET /health/ready`. The migration is not applied unless `apply_migration` is enabled. Provision the service-specific certificate, JWKS, Ed25519 proof/bundle public keys and external topic ACLs before deployment; no development/insecure fallback is provided. Certificate rotation, metrics/tracing, deployment manifests, and an integration run against provisioned dependencies remain release tasks.
